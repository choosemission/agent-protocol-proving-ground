# The x401 door

A resource behind **x401 0.2.0 as published at
[`proof/x401@7e864af`](https://github.com/proof/x401/blob/7e864af97cd8202a5380386f52939d759541977d/spec.md)**.
It implements the draft as of that commit. It claims nothing about conformance.

Code: [`x401.ts`](x401.ts). Reference agent and wallet: [`client.ts`](../../client.ts),
about 100 lines, meant to be read next to the spec.

```sh
node client.ts http://pg.localhost:8401/pg/doors/x401/r/<run>            # signed request
node client.ts http://pg.localhost:8401/pg/doors/x401/r/<run> --unsigned # unsigned request
```

## The exchange

1. **Challenge.** A request without proof gets `401` and `PROOF-REQUEST`: a
   base64url x401 payload with two entries in `credential_requirements.digital.requests`:
   - `openid4vp-v1-signed`: a JAR signed by the verifier, with `client_id`
     `decentralized_identifier:did:webvh:<scid>:<host>`. The key is in the DID log at
     `/.well-known/did.jsonl` (also served as a parallel `did:web` at `/.well-known/did.json`).
   - `openid4vp-v1-unsigned`: the same OpenID4VP request, unsigned.

   Both carry one fresh nonce, valid for five minutes, and this DCQL query:
   a `dc+sd-jwt` credential of vct `<BASE_URL>/pg/vct/handle` disclosing
   `handle`. On a run's URL the query pins `handle` to that run's handle; on
   the anonymous URL any Lab-attested handle will do. The body repeats the
   payload for callers that can't read headers. There is no `oauth` member,
   because the door does no token exchange.
2. **Credential.** The Lab handle credential, from `POST /pg/issuer/credential`
   (see the [README](../../README.md#the-handle-credential)).
3. **Retry.** The same URL with `PROOF-RESPONSE`: a Result Artifact whose
   `credential_result` is `{protocol, data: {vp_token: {lab_handle: [<sd-jwt>~<kb-jwt>]}}}`,
   inline or by `credential_result_uri` (https only, never a private address).
4. **Through:** `200`, `{through: true, handle, receipt}`, and `PROOF-RESULT`
   carrying `{scheme, version, result: "accepted", receipt}`.
   **Stopped:** `401` and `PROOF-RESULT` carrying an x401 Error Object with
   the step it stopped at (`stopped_at`) and an `error_uri` that opens the
   attempt's timeline on the wall.

## The ladder

An attempt is scored by the highest step it reached. Each step links to the
spec section it comes from, on the wall.

| Step | Checks | Stop codes |
| --- | --- | --- |
| challenged | The door issued a PROOF-REQUEST and a nonce | |
| retried | A PROOF-RESPONSE came back on the same route | |
| artifact decoded | One base64url JSON Result Artifact, a known protocol, a presentation ending in a KB-JWT | `invalid_artifact`, `token_not_supported`, `invalid_reference` |
| nonce matched | Issued by this door, on this run's URL, unexpired, and not used before. It is spent here | `nonce_unknown`, `nonce_other_run`, `nonce_expired`, `nonce_replayed` |
| signature valid | Issuer JWT (Lab issuer key, or the `x5c` header), every disclosure digest, the KB-JWT against `cnf.jwk` (at most 5 minutes old), and `sd_hash` | `issuer_key_unresolved`, `invalid_signature`, `invalid_disclosure`, `no_holder_key`, `sd_hash_mismatch` |
| binding valid | Signed: KB-JWT `aud` is the verifier's `client_id`. Unsigned: `aud` is `origin:<origin>` | `binding_mismatch` |
| query met | vct matches, `handle` is disclosed and, on a run's URL, is that run's handle. The timeline notes any claim disclosed that the query didn't ask for | `query_not_met` |
| issuer trusted | `iss` is the Lab test issuer | `untrusted_issuer` |
| through | All of the above | |

The plan's sketch has *request decoded* before *retried*. The door can't see
an agent decode its request, so this ladder uses steps the door can observe.

## The receipt

An ES256 JWT, `typ: pg-receipt+jwt`, signed by the verifier (`kid` `<did>#verifier`).
Verify it against `/pg/jwks.json` or the DID document.

```json
{
  "iss": "did:webvh:<scid>:pg.localhost%3A8401", "sub": "<attested handle>", "jti": "<attempt id>", "iat": 0,
  "door": "x401", "spec": "x401 0.2.0 (proof/x401@7e864af)", "resource": "<BASE_URL>/pg/doors/x401",
  "request_mode": "openid4vp-v1-signed", "steps": ["challenged", "…", "through"],
  "proves": "A fact about the holder, attested by an issuer", "trusted_issuer": "did:webvh:<scid>:pg.localhost%3A8401"
}
```

It records that the attempt got through. Its `sub` is the handle the holder
disclosed, which is public on the wall anyway; it carries no other claim.

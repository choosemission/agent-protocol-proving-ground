## 2026-11-13 01-oid4vci-issuer task 5: did:key → JWK
Done: `didKeyToJwk(kid)` in `oid4vci.ts` covers Ed25519 → OKP and P-256 → EC, with the point decompressed by `ECDH.convertKey`, and refuses a fragment mismatch, a bare DID and other multicodecs. Changed from the spec: no hand-rolled base58, since `didwebvh-ts` (already a dependency) exports `multibaseDecode`. Vectors: the spec's links to its test-vector files are dead (404), so P-256 uses decentralized-identity/did-key.rs's from_secret_key vector (secret → did:key; node derives the expected JWK), and Ed25519 uses RFC 8037 A.1's key, encoded with didwebvh-ts. Tested: `node --test test/oid4vci.test.ts` → pass, `tsc` clean. Next: task 6.
## 2026-11-13 01-oid4vci-issuer task 6: credential endpoint
Done: `POST /pg/issuer/credential` with a bearer token and `proofs.jwt: [one proof]` issues the handle credential with `cnf.jwk` = the proof's key. The key comes from a did:key `kid` or a header `jwk`: exactly one, no `x5c`. jose checks `typ`, alg ∈ {ES256, EdDSA}, `aud`, `iat` (≤5 min old, not in the future; probed) and refuses a header `jwk` that carries `d`. The nonce is spent only after the proof verifies. Errors are `invalid_token` (401), `invalid_credential_request`, `unknown_credential_configuration`, `invalid_proof` and `invalid_nonce`. Checked the credentials wallet: it signs Ed25519 proofs as `EdDSA` (credentials-wallet-mcp `sd_jwt_vc.rs:74`), so the alg list matches it. Tested: `npm test` → pass (4 happy paths, refusals). The "no token" refusal moves to task 8, because until then a request without `Authorization` still reaches the plain POST. Next: task 7.

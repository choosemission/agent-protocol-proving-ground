## 2026-11-13 01-oid4vci-issuer task 3: token endpoint
Done: `POST /pg/issuer/token` swaps a form-encoded pre-authorized code for a 5-minute opaque Bearer token (`no-store`). Spent, expired or unknown codes give `invalid_grant`, and other grants give `unsupported_grant_type`. `oid4vci.serve` handles everything under `/pg/issuer`. The plain POST keeps `/pg/issuer/credential` when there's no bearer token, until task 8. Tested: `node --test test/oid4vci.test.ts` → pass (both codes from task 2 redeemed, then refused), e2e still green, `tsc` clean. Next: task 4.

## 2026-11-13 01-oid4vci-issuer task 5: did:key → JWK
Done: `didKeyToJwk(kid)` in `oid4vci.ts` covers Ed25519 → OKP and P-256 → EC, with the point decompressed by `ECDH.convertKey`, and refuses a fragment mismatch, a bare DID and other multicodecs. Changed from the spec: no hand-rolled base58, since `didwebvh-ts` (already a dependency) exports `multibaseDecode`. Vectors: the spec's links to its test-vector files are dead (404), so P-256 uses decentralized-identity/did-key.rs's from_secret_key vector (secret → did:key; node derives the expected JWK), and Ed25519 uses RFC 8037 A.1's key, encoded with didwebvh-ts. Tested: `node --test test/oid4vci.test.ts` → pass, `tsc` clean. Next: task 6.
